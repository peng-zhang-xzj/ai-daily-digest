# L3 BLIP-2与Flamingo：怎样把会看图的模型接到会说话的模型

建议时长40–45分钟。前置：L1的加权读取、L2的图文特征。学完应能区分“视觉信息从输入前缀进入”与“在语言层中被读取”，解释Q-Former和Perceiver Resampler如何压缩视觉序列。

## 1. 两个强模型为什么不能直接插线

假设视觉编码器输出`A:[L,Dv]`，语言模型处理向量`[序列长度,Dl]`。Dv与Dl可能不同，这是尺寸问题；即使相同，视觉特征的数值分布与语言词嵌入也不同，这是学习接口问题。还要决定视觉信息从哪里进入LLM：当成前缀token，还是让语言层通过交叉注意力读取它。

为什么不直接把两侧全部重训？视觉编码器和LLM已用大量数据训练；全量训练成本高，新图文数据可能又不足以保留原有能力。冻结原模型、只训练桥接部分，是一种借用已有能力的工程选择。冻结表示不更新参数，并不表示不能做前向计算，也不表示它没有任何输入梯度路径。

## 2. 先统一理解query、key、value

query即一次读取需求，key用于判断哪个位置匹配需求，value是最后被读取的内容。它们不是三份独立标注，而是输入向量经过不同投影得到的表示。

一次点积交叉注意力可写成：

`Attention(Q,K,V)=softmax(QKᵀ/√d)V`。

若Q有M行、K和V有L行，则相似度矩阵为`[M,L]`，softmax对L个可读位置归一化，输出仍有M行。这里d是每个query/key的向量宽度。也就是M个需求分别从L个视觉位置读取一次，得到M个结果。√d用于抑制维度增大时点积分布尺度增长；它不保证不同模型都拥有相同的温度或校准。

多头注意力先把向量映到不同子空间，每个头单独读，再拼接与投影。不能简单把每个头解释成“一个识别颜色，一个识别动物”：这种分工不是人工规定，也未必如此稳定。

## 3. BLIP-2的Q-Former：让少量query替LLM提取视觉信息

Q-Former是一组可学习query加一个Transformer。以经典配置为例，使用32个query，每个query最初是一条可学习的向量，不对应“狗/天空/人物”这样的固定类别。训练后它们可形成互补的读取行为。

query之间可以通过自注意力交流，又通过交叉注意力读取冻结视觉编码器的A。最后得到32个视觉相关输出，再投影到LLM输入维度，作为视觉前缀交给冻结LLM。

```text
图像 → 冻结视觉编码器 → L个视觉特征 A
                            ↑ K,V
32个可学习query → 自注意力 + 交叉注意力 → 32个浓缩输出
                                                  ↓ 线性投影
                                              32个LLM前缀
文本词嵌入 ────────────────────────────────────┬─────┘
                                               ↓
                                         冻结LLM生成文字
```

query没有“先知道该抽取什么”的魔法；训练目标告诉整个Q-Former，提取哪些信息能更好完成图文匹配或生成。32是一个模型设计选择，不是所有任务的最佳压缩率。

## 4. 先手算一个query，再看维度与压缩量

[[figure:l3-query-read]]

为了手算，省略√d缩放和可学习投影，设Q只有一行q=(1,0)，K=V包含三行(1,0)、(0,1)、(1,1)。分数为(1,0,1)，softmax约为(0.4223,0.1554,0.4223)，输出是(0.8446,0.5777)。

再取query q₂=(0,1)，分数为(0,1,1)，权重约(0.1554,0.4223,0.4223)，输出为(0.5777,0.8446)。两个query读出不同混合；输出行数由query数量决定，而不是由图像patch数量决定。

真实场景若A有576行，Q-Former输出32行，则LLM侧视觉长度降到约1/18。**这不代表整个系统成本按同一比例下降**：视觉编码器仍要计算原图，Q-Former交叉注意力仍需处理32×576个query—位置关系，LLM还要处理文本。更强压缩也可能损失小字、对象数量与精确位置。

## 5. BLIP-2为什么分训练阶段

第一阶段让Q-Former学会有效连接图像与文字。经典方案包含三类任务：图文对比要求整体表示匹配；图文匹配判断图文是否为一对；以图像为条件生成文本要求query抽出的信息足以支持描述。不同任务会使用不同注意力掩码，控制query与文本的交流，不能把三种任务当同一个loss的别名。

第二阶段连接冻结LLM。Q-Former输出经投影变成LLM输入，文本生成损失继续调整Q-Former与投影。LLM参数可以不更新，但它对前缀如何影响下一词概率的计算，仍会提供梯度给桥接部分。

这里“冻结双塔”不表示整个过程只有一个线性层在训练。Q-Former本身是有参数、有多层注意力的模块；冻结节省的是两大已有模型的更新，而不是免除新桥的训练。

## 6. Flamingo：视觉信息不只是在最前面塞一段前缀

Flamingo保留视觉编码器与语言模型，引入Perceiver Resampler，把变长的图片/视频特征重采样成固定数量视觉latent。它同样使用可学习latent向视觉特征做交叉注意力，但不能仅凭“都有query”说它就是Q-Former的同名变体。

随后在语言模型的若干层之间插入可训练的gated cross-attention模块。语言层的hidden states作为Q，视觉latent作为K/V，语言表示可在中途再次访问视觉信息。输出用门控残差合回语言流，例如示意为：

`h_new = h + tanh(g) × CrossAttention(h, visual_latents)`。

g是可学习门控参数，可初始化为0，让开始训练时视觉新分支贡献接近0，保留已有语言行为；之后逐渐学会使用视觉证据。实际块还包含其他层，公式只展示门控残差的核心，不代表整套Flamingo实现。

## 7. 多图交错与few-shot具体怎么工作

提示可以组织为“图1→问题1→答案1→图2→问题2→答案2→新图→新问题”。语言模型沿交错序列处理示例；视觉访问掩码决定某段文本可以读取哪些图像，避免把未来图像或无关图片当条件。图像位置标记只是结构边界，图片本身仍通过视觉分支提供特征。

few-shot的含义是推理时在上下文里给几个例子，让模型模仿任务规则，例如先给两张图的“只回答颜色”示例，再问新图。没有因此更新参数；更新的是上下文。它可能帮助模型理解格式，却不能保证新增的视觉概念被少量示例彻底学会，也会受示例顺序、格式和上下文长度影响。

## 8. 放在同一张表里，差异才看得清

[[figure:l3-bridge-comparison]]

| 设计 | BLIP-2典型路径 | Flamingo典型路径 |
|---|---|---|
| 压缩模块 | Q-Former query读取视觉特征 | Perceiver Resampler重采样 |
| 视觉信息进入语言侧 | 浓缩query投影为输入前缀 | 语言层内新增gated cross-attention |
| 谁提供读取需求 | Q-Former的query及其任务训练 | 压缩latent与语言hidden state分两层读取 |
| 典型教学重点 | 冻结LLM也能学习输入接口 | 多图交错、视觉重读与in-context学习 |

连接器选择没有脱离任务的“最先进”。如果目标是OCR，压成32行可能过度；如果要处理很多图，固定latent能控制语言侧长度；如果要尽量复用现成LLM代码，输入前缀通常比改每层结构更简单。

## 9. 可运行的交叉读取最小代码

```python
import torch
q = torch.tensor([[1., 0.], [0., 1.]])
visual = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])
weights = (q @ visual.T).softmax(-1)  # 手算示例省略缩放
latent = weights @ visual
print(weights.shape, latent.shape)  # [2,3]、[2,2]
print(latent)                       # 约[[.8446,.5777],[.5777,.8446]]
```

它只模拟query读取，不是完整Q-Former。真正实现还需投影、残差、归一化、多头、多层、训练任务与掩码；漏掉这些，不能把三行代码称成可用BLIP-2。

## 练习

1. 输入576个视觉位置、32个query，cross-attention权重是什么形状？——答：每个头通常为`[32,576]`，输出32个向量。
2. 冻结LLM后，答案loss能训练前缀投影吗？——答：能，只要输入前缀参与计算图且未切断梯度。
3. 图像被压为32个token是否等于读图成本降低18倍？——答：只描述进入LLM的视觉序列压缩，不包含视觉编码器和桥接模块成本。
4. few-shot示例是在微调参数吗？——答：不是，它们是推理上下文。
5. 为什么固定latent对多图友好，却可能不利于小字？——答：控制序列预算，但有限瓶颈可能难以保留高密度细节。

下一讲将看到另一种取舍：不先用复杂query压缩，而是把patch直接投影成LLM可读向量，再用指令数据训练接口。

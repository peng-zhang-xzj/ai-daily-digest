# L2 CLIP与对比学习：让图片和文字学会互相认出

建议时长40–45分钟。前置：知道向量和本课L1的编码器含义；本讲解释点积、归一化和对比损失。学完应能手算一个图文匹配batch，解释zero-shot分类，并指出CLIP为什么不能直接回答开放式问题。

## 1. 从“怎么读图”到“读出的特征为什么懂语义”

L1的注意力能改变读取位置，但读取到的视觉特征是否理解“金毛”“滑雪”或“手持红球”，仍取决于训练。传统分类训练把图片映到固定标签，假设只有1000类，模型的训练目标就只区分这1000类；如果想增加“在水中奔跑的狗”这种复杂类别，固定标签体系很难扩展。

网络图片常有描述、标题或alt文本。它们虽然嘈杂，却给出了比类别名丰富的监督。CLIP的想法是：同时训练图像编码器和文本编码器，让正确配对的图文在一个共同空间里相似，错误配对的图文不相似。它不是把所有图片转成文字，而是让两种输入各自产生可比较的向量。

## 2. 两个编码器与一个共同空间

图像编码器f把图像I变成向量v；文本编码器g把描述T变成向量t。两边原始输出维度可能不同，因此各自有投影层映到相同维度d。

`v = normalize(project_image(f(I)))`

`t = normalize(project_text(g(T)))`

normalize把向量除以自身长度。二维向量(3,4)长度是5，归一化后为(0.6,0.8)。对已归一化向量，点积`v·t`等于它们夹角的余弦，相似方向得高分，正交得0，相反方向得−1。这个相似度是学到的表示关系，不是天然的“事实相同”判定器。

视觉侧可以是CNN，也可以是ViT。ViT先把图像分成patch，把每个patch投影成向量，用Transformer在patch之间交换信息。CLIP图文对比通常比较的是汇总后的全图向量；后续VLM经常取视觉Transformer内部的patch特征，保留细节。**全局对齐目标和局部特征用途是相关但不同的两件事。**

## 3. 一个batch如何制造监督信号

设一次训练取N个图文对`(I₁,T₁)…(Iₙ,Tₙ)`。把图像向量排成矩阵X，文本向量排成Y，两者形状都是`[N,d]`。计算：

`S = X Yᵀ / τ`。

S形状为`[N,N]`；Sᵢⱼ表示第i张图与第j段文本的匹配分数。τ是正的温度，控制softmax的尖锐程度；温度越小，同样的相似度差会被放大。实际CLIP学习一个相应的缩放参数，并需要稳定性处理。

如果batch按配对顺序组织，正确匹配就在矩阵对角线上。图到文任务：固定第i张图，要求它在N段文本中选第i段；文到图任务：固定第j段文本，要求它在N张图中选第j张。每个配对既提供正例，其他batch样本又提供候选负例。

图到文概率与损失是：

```text
P(Tⱼ | Iᵢ, 这个batch) = exp(Sᵢⱼ) / Σₖ exp(Sᵢₖ)
L_image = (1/N) Σᵢ −log P(Tᵢ | Iᵢ, 这个batch)
L_text  = 对S的列做同样的正确配对损失
L = (L_image + L_text)/2
```

“这个batch”不能省略理解：这里的概率只是在候选集合中匹配的概率，不是句子真实与否的普遍概率，也不是生成这段文本的概率。

## 4. 手算2×2：损失怎么把正确配对拉近

[[figure:l2-clip-pairs]]

设两张图与两段文本都得到单位向量：`v₁=t₁=(1,0)`，`v₂=t₂=(0,1)`。温度τ=0.5，那么S是：

| | 文本1 | 文本2 |
|---|---:|---:|
| 图1 | 2 | 0 |
| 图2 | 0 | 2 |

图1选文本1的概率为`e²/(e²+e⁰)=0.8808`。正确项损失为`−log(0.8808)=0.1269`。图2和文到图同理，平均损失也为0.1269。

若编码器把两张图都输出成同一向量，分数无法区分候选，正确匹配概率可退化到0.5，损失约0.6931。模型因此受到压力去编码能区分配对的内容。

对某一行，交叉熵对分数的梯度是`预测概率−目标指示值`。正确项的目标是1，若预测0.8808，梯度约−0.1192，更新倾向提高该分数；错误项目标0，梯度为正，更新倾向降低分数。这就是“拉近/推远”的计算含义，不是把两个物理点真的搬动。

若τ从0.5降为0.25，分数变成4与0，概率约0.9820。它更确信，却不意味着编码器真的变得更懂图片；错误配对同样会被更确信地判断错误。温度是训练与校准参数，不能单独充当能力指标。

## 5. 最小实现与数据对应

下面是双向对比损失的CPU算例。实际训练把X/Y换成真实编码器输出；这里只验证矩阵与损失。

```python
import torch
from torch.nn import functional as F

X = torch.tensor([[1., 0.], [0., 1.]], requires_grad=True)
Y = torch.tensor([[1., 0.], [0., 1.]], requires_grad=True)
Xn, Yn = F.normalize(X, dim=-1), F.normalize(Y, dim=-1)
scores = Xn @ Yn.T / 0.5
labels = torch.arange(2)       # 对角线为正确图文配对
loss = (F.cross_entropy(scores, labels)
        + F.cross_entropy(scores.T, labels)) / 2
loss.backward()
print(scores.detach())        # [[2,0],[0,2]]
print(round(loss.item(), 4))  # 0.1269
print(X.grad)                # 图像侧也收到对比目标的梯度
```

实现时要保证图文配对索引没有打乱。若多GPU聚合负例，标签需要对应全局候选位置；若只局部聚合，却用全局标签，会出现静默的监督错误。也要检查输入归一化、温度与数值精度，不能把“模型不收敛”一概归咎于数据量。

## 6. 不训练新分类头，怎么做zero-shot分类

[[figure:l2-clip-zeroshot]]

给一张从未在指定下游训练集微调过的图片，以及候选类别“狗、猫、汽车”。把每个类别放进文本模板，如“a photo of a dog”；文本编码器给出三个向量。图像编码器给出v，比较与三者的相似度，最大值对应预测类别。

为什么比直接输入“dog”常更好？因为预训练文本多是描述性句子，模板更接近训练分布。可以给每类多种模板，先归一化、平均、再归一化，形成更稳定的类别表示。不同语言、模板和候选类别集合都会改变结果，因此读zero-shot数字要问设置。

zero-shot不是“模型没见过任何狗”，而是没有在这个特定下游分类任务上进行相应训练。网络预训练可能已经见过大量狗以及类别名称。它也不说明没有数据污染；训练图文与评测图像重合仍须检查。

## 7. SigLIP改变了哪一步

CLIP的softmax把一行N个候选放在同一个分母里，相互竞争。SigLIP把每个图文配对看作一个二分类：匹配为正，不匹配为负。令标签y取+1/−1，z为缩放相似度加可学习偏置，则单对损失可写成：

`L_pair = −log sigmoid(yz)`。

正例希望z大，负例希望z小；不需要每个样本都在softmax里与所有候选共享归一化分母。这改变了损失组织及分布式实现的约束，但仍需要设计正负比例、负例采样、batch和偏置。不能从“用了sigmoid”直接推出所有设置更省、更稳或更准确。

## 8. CLIP能做什么，不能保证什么

它擅长建立可复用的图文语义相似度，支持检索、开放词表分类和视觉编码器初始化。它没有在这里使用自回归文字解码器，因此不会仅凭对比损失生成一段解释。

全图匹配目标也可能忽略数量、否定、关系和小字。“两只狗”与“三只狗”共享主要语义，“狗追人”与“人追狗”都包含相同实体；如果训练监督不足，向量可很相近。背景与主体共现会形成捷径，错误alt文本也可能让模型学错关联。

还有一个常见误区：CLIP视觉空间对齐的是它自己的文本编码器输出，并不等于已对齐Vicuna/Qwen的词向量。维度一致也不代表语义接口一致。下一讲的连接器与后续训练就是为了处理这个新接口。

## 练习

1. N=32、d=768时，X、S形状分别是什么？——答：`[32,768]`和`[32,32]`；S不是视觉patch网格。
2. 一批中两段描述都正确描述同一类狗，能把其中一段当绝对负例吗？——答：未必，它可能是假负例；训练需要关注配对噪声和重复语义。
3. 把候选类别加一项，会改变softmax概率吗？——答：会改变分母；原有相似度本身可以不变。
4. 图文相似度高，能证明图片里不存在违规元素吗？——答：不能，匹配分数不是该风险标签的完整证据，局部细节还可能被全局表示忽略。
5. CLIP对齐后为什么还要训练VLM连接器？——答：LLM的维度、语义分布和生成目标不同，新的跨模态接口需要适配。

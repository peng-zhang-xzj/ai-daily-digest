# L4 LLaVA：一张图片怎样作为“连续前缀”进入大语言模型

建议时长40–45分钟。前置：知道视觉特征、向量投影和逐词生成；本讲从输入到输出逐步解释。学完应能算出576的来源，画出拼接后的序列，说明两个训练阶段各更新什么，以及为何极简结构仍需要高质量指令数据。

## 1. 极简方案解决的是接口，不是取消视觉学习

Q-Former先压缩，Flamingo在语言层内插入视觉读取。LLaVA选择更直接的路线：把视觉patch特征投影成与LLM词嵌入同维度的连续向量，作为序列的一部分输入LLM；再用图文描述和视觉指令训练这条接口。

“简单”指新增结构少，不是模型尺寸小，也不是只训练几条数据就能可靠。一个巨大且已训练好的视觉编码器与语言模型仍然是底座。没有训练接口，随机投影后的视觉向量即使尺寸正确，也不是语言模型能稳定解释的条件。

## 2. 先分清版本，才能讨论具体数字

[[figure:l4-llava-versions]]

| 示例 | 图像输入 | ViT patch | 视觉patch数 | 连接器 |
|---|---|---|---:|---|
| 初版LLaVA典型配置 | 224×224 | 14×14 | 16×16=256 | 线性投影 |
| 本讲LLaVA-1.5-7B | 336×336 | 14×14 | 24×24=576 | 两层MLP |

这是代表配置，不能把“LLaVA”这个系列名当作所有版本固定576的保证。不同checkpoint和预处理可能有不同输入、token组织和隐藏维度。下面固定使用1.5的典型接口解释，因此所有shape都跟这个例子对应。

## 3. 从像素到视觉特征，逐步看shape

一张RGB图片原始是`[H,W,3]`。预处理先缩放/裁剪或按该checkpoint规则处理成336×336，并归一化像素值。原图本来是672×672，并不意味着这个固定分辨率模型就读取了672×672的细节；processor可能仍输出336×336。

进入视觉编码器时，常用张量格式是`[B,3,336,336]`，B表示一次处理多少张图。每个14×14×3的patch有588个原始数字，通过可学习patch投影映成视觉向量，然后在视觉Transformer里与其他patch交换信息。

CLIP ViT-L/14的patch特征典型宽度为1024。视觉模型内部还可能有汇总用的CLS token，产生577个位置；LLaVA通常选择指定层的patch特征、去掉CLS，得到`[B,576,1024]`。取哪一层、是否去CLS，是模型配置，不是随意可替换的细节。

因为ViT已经让patch彼此交流，一个patch输出向量可以包含其他位置的信息。因此“576个patch token”不等于“576个互不联系的小图片标签”。

## 4. 连接器改变维度，保留位置数量

1.5的MLP可示意为：

`Z = W₂ GELU(W₁ A + b₁) + b₂`。

A的形状是`[B,576,1024]`，第一层把每行映到4096维，经过GELU非线性，第二层输出4096维。这里4096对应本例Vicuna-7B的语言隐藏宽度，不是所有LLM统一宽度。

因此Z形状为`[B,576,4096]`。MLP沿最后一维作用于每个位置，不把576压成32，也不生成576个离散词表id。对每个patch，模型得到的是可直接作为LLM输入的连续向量。

这个两层投影大约有`1024×4096 + 4096×4096 + 两个bias`，约2098万参数。相对7B语言模型，新接口较小；但前向、激活和训练数据成本依然存在。“只更新连接器”也不等于“完全不运行LLM”。

## 5. 与文字怎么拼：token id与输入向量不能混为一谈

[[figure:l4-llava-shapes]]

文本先由tokenizer切成离散id，再通过embedding表查出`[B,T,4096]`的向量。视觉分支不查这个表，直接提供Z。模型最终接收到同一宽度的一串向量，例如：

```text
[对话前缀文字向量]
[视觉向量1]...[视觉向量576]
[问题文字向量：图里有什么？]
[助手回答前缀]
```

源码中的`<image>`常是放置图像的边界标记，不是整张图只占一个向量。不同实现可能在模型内部用视觉向量替换标记，也可能在processor里展开相应占位token；最后要以LLM实际接收的向量长度为准，不能只打印原始字符串就宣称“图像仅一个token”。

进入LLM后，因果掩码让每个输出位置只能读取之前的位置，避免在训练时偷看未来答案。位置编码、对话模板和attention mask也必须一致。视觉信息的位置安排可以变化，不保证总是最前面；本图展示一种常见组织。

LLM无需另一个专门的“看图语法解析器”，但这也不意味着视觉与词在语义上完全相同。它们只共享输入接口与后续计算维度，训练让模型学会利用不同来源的表示。

## 6. 两阶段训练分别解决什么

阶段一，特征对齐：用图像与描述，冻结视觉编码器和LLM，只更新投影。训练目标是让视觉前缀帮助冻结LLM预测描述文本。这与CLIP双塔的对比损失不同：这里已经经过语言解码器，以生成词为目标训练新接口。

阶段二，视觉指令微调：用“图像+用户问题+助手回答”的数据，继续更新连接器，并更新LLM，典型1.5仍冻结视觉编码器。模型学习的不只是图里有哪些东西，还包括按问题选择信息、组织回答、遵循格式和多轮上下文。

若只有“狗在草地上”的caption，模型可能会描述，却不会自动懂“只返回JSON”“给我三条依据”。反过来，若只有精美对话但视觉事实不忠实，模型容易把错误细节也学进生成习惯。

## 7. GPT-4合成指令具体做了什么

初期缺少大规模图像—对话数据。LLaVA让纯文本GPT-4读取图像已有的caption与物体框等文字信息，再生成描述、多轮问答或推理题。例如给“狗在草地上”和狗、球的位置框，可以要求生成“球在狗的哪一侧”这类问题。

纯文本GPT-4没有直接看到原图；它只能依赖输入的符号描述。若caption没有写天气，GPT-4补出“晴朗蓝天”就可能无依据；若边界框信息有误，生成空间推理也可能误导。所谓合成省人工，不等于零成本：有API调用、图像源准备、去重、过滤和验证成本。

初版论文描述158K规模的合成指令样本；1.5后续还引入学术VQA等混合数据。不能把“初版怎么造数据”说成所有版本训练集完全相同。读新模型时应把架构、数据、训练阶段作为一起变化的配方。

## 8. 可运行接口算例：连续视觉向量不需要词表id

下面用小维度模拟接口。它没有视觉编码器和已训练的LLM，只验证形状与因果序列组织。

```python
import torch
from torch import nn

torch.manual_seed(4)
vision = torch.randn(1, 4, 16)     # 4个视觉位置
projector = nn.Sequential(nn.Linear(16, 32), nn.GELU(), nn.Linear(32, 32))
word_embedding = nn.Embedding(100, 32)
text_ids = torch.tensor([[10, 11, 12]])
visual_inputs = projector(vision) # [1,4,32]，没有视觉离散id
text_inputs = word_embedding(text_ids) # [1,3,32]
sequence = torch.cat([visual_inputs, text_inputs], dim=1)
causal_mask = torch.triu(torch.ones(7, 7, dtype=torch.bool), diagonal=1)
layer = nn.TransformerEncoderLayer(32, 4, 64, dropout=0., batch_first=True)
hidden = layer(sequence, src_mask=causal_mask)
print(sequence.shape, hidden.shape)  # [1,7,32]、[1,7,32]
```

这里的True表示阻止读取未来位置。生产模型还需要与checkpoint相符的位置编码、模板、缓存等；此代码不能代替完整LLaVA推理。真实processor接口实验在Lab中，可以验证336/672输入都得到576视觉占位token。

## 9. 极简范式的收益与边界

收益是结构容易复用：视觉编码器、投影、现成LLM形成清晰边界，数据与训练方式可以独立实验。局限也沿这条链路出现：低分辨率可能先丢小字；不压缩的patch输入让语言序列变长；指令合成会引入幻觉；语言先验可能盖过视觉证据。

例如问图片里小标签上的价格，原图数字本来清楚，但预处理到336后不可辨认，后续更强LLM也无法从被删除的信息里可靠恢复数字。“回答更流畅”不说明“看得更清”。下一讲的数据以及L6分辨率和连接器，是继续拆解这些瓶颈。

## 练习

1. 336输入、patch14、去掉CLS后有多少视觉位置？——答：24×24=576；若保留CLS则另加1，不能混算。
2. `[576,1024]`经逐位置MLP变为`[576,4096]`，是否增加了图像实际细节？——答：改变表示接口，不凭空恢复输入已丢失的信息。
3. 为什么图像不需要一个576项“视觉词表”？——答：本路径用连续向量直接进入LLM，视觉位置数不等于离散词表大小。
4. 阶段一LLM冻结，为什么仍需要运行它？——答：描述概率和损失来自LLM前向，梯度需经其计算传回投影。
5. 两种模型都叫“视觉指令微调”，数据配方是否一样？——答：不一定，要逐个检查数据来源、格式、规模、质量和冻结策略。

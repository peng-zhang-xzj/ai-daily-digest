# L6 结构进化：看清小字、控制视觉长度、保留二维与时间位置

建议时长60–70分钟，可分成两个课时。前置：L4的patch、投影与LLM输入；本讲重述必要的注意力和位置概念。学完应能比较三种分辨率路径，手算patch与合并后的token，推导RoPE相对位置性质，并给图像/视频token正确赋坐标。

## 1. 一个具体失败：原图清楚，模型却读错金额

输入一张1000×1400发票，上面的小字高约12像素。若先缩放到336级别，小字可能只剩约3–4像素，笔画混在一起。此时模型输出一个流畅金额，可能只是依据账单先验猜测，不是读到了数字。

必须先问：信息是在预处理、视觉编码、token压缩、语言推理还是答案提取阶段丢失？增大LLM不一定修好前几步。结构设计就在“保留细节”和“计算预算”之间做选择，不能只看某层参数量。

## 2. 视觉编码器内部发生了什么

对处理后尺寸H×W、patch边长p，若H/W恰好可整除p，patch数为：

`Npatch = (H/p) × (W/p)`。

每个patch映成向量，再加位置相关信息并进入视觉Transformer。自注意力让每个位置根据自己的query对其他位置的key打分，再加权读取value。若N个位置彼此全局读取，每个头的相似度有N×N项。

视觉输出不只是原patch像素的独立投影，它已经混入上下文。层数、特征宽度、位置编码、训练数据都影响表示。CLIP、SigLIP和自训ViT只是不同初始化/训练路线，不能把“所有VLM视觉侧都是现成冻结CLIP”当普遍规则。

## 3. 三种分辨率路径，需要同时讲全局、局部与预处理

第一种，固定低分辨率：例如LLaVA-1.5按checkpoint规则得到336×336图，视觉长度固定576。接口简单、成本可预估，但小字可能先被缩小，非方图还可能受到裁剪/填充等处理影响。

第二种，AnyRes切图：把较大画布切成多个固定大小crop，每块走已有固定分辨率视觉编码器；常另外保留一张全局缩略图，帮助识别整体场景。它不要求把原ViT完全改成变长输入，但要组织crop的顺序、恢复局部空间关系、处理padding与重复。

第三种，原生动态分辨率：视觉编码器接收可变网格，不把所有图强制塞成同一正方形。processor通常仍会限制最小/最大像素并把尺寸对齐到某个倍数，“原生”不意味着任意大图片可以无限制原样输入。不同长宽比会产生不同网格及视觉长度。

它们是工程取舍，不是新方案天然全面胜出。切图可以复用强大的固定ViT，但crop边界可能切断表格关系；动态分辨率保留统一网格，却需要编码器、批处理和位置机制支持变长输入。

## 4. 连接器与压缩到底压了什么

逐位置MLP改变向量宽度，不改位置数。Q-Former/Resampler使用少量query，从许多视觉位置读取固定数量latent。另一类是空间合并：把邻近2×2位置的特征拼接或聚合，再用可学习投影输出一个语言侧向量。

2×2合并将位置数除以4，但不是必然把信息简单平均扔掉。若先拼接四个D维向量，暂时得到4D维，再投影到输出宽度，模型有机会编码局部结构；仍然存在表示瓶颈，不能据此保证零信息损失。

这些机制可以组合，但教学开关的组合不一定对应某个真实checkpoint。例如“AnyRes再2×2压缩”在本互动中用于理解算力变化，不应声称原始LLaVA-NeXT默认就采用这个组合。

|---|---:|---:|

| 672×672，切成4块336，再加全局图 | (4+1)×576=2880 | 2880 |
| 上一教学切图再合并 | 2880 | 720 |

真实LLaVA-NeXT会选择允许的画布、处理unpadding并加入newline等结构标记，实际长度不能都拿这个简式代替。Qwen2.5-VL则按真实processor的grid计算，图像网格为`[t,h,w]`，空间合并后长度为`t×h×w/4`。

本课CPU实测：LLaVA-1.5的336与672原输入，处理后都为336，均576视觉token；Qwen2.5-VL的336输入grid为[1,24,24]，合并后144；672输入grid为[1,48,48]，合并后576。两模型都出现576，不代表看到了相同分辨率，也不代表效果相同。

若H=448、W=672，14像素patch得到32×48=1536，合并后384。这说明分辨率不能只展示“边长平方”：长宽比也是模型实际输入的一部分。

## 6. 为什么“token平方”不等于实际耗时平方

全局注意力需要处理N×N个位置配对，固定宽度时核心注意力项近似随N²增长。若只看视觉长度，672不合并相对336有4倍token，对应16倍长度平方项。边长翻倍→面积4倍→注意力项16倍，三个层次不能说成同一个“平方”。

LLM真正处理的是视觉+文本等总序列。若文本300token，基线视觉576，则总长度876；切图视觉2880时总长度3180，长度平方比约为`3180²/876²=13.18`，而仅视觉比为25。二者回答的是不同问题，界面应说明比较时文本预算是否固定。

注意力之外还有线性投影、MLP、视觉编码器、连接器和输出层。FlashAttention可避免完整注意力矩阵物化带来的大量内存读写，却不消除全局配对计算的二次项。预填充prefill一次处理已有序列；有KV缓存的decode每步通常是新query读取已有K/V，单步对上下文长度的注意力项近似线性，并不是每步重算整张N×N矩阵。

Qwen2.5-VL视觉侧多数层采用window attention，在局部窗口内读取，另保留部分全局层；固定窗口大小时局部层的配对数随总patch数近似线性。这与LLM侧全局因果注意力是两个计算阶段。

## 7. 不加位置机制，模型为什么不知道谁在谁右边

注意力主要比较向量内容。两块相同的文字patch若内容很像，仅靠内容相似度难以表达“上方标题”和“下方金额”的位置。文本有先后顺序，图像有高/宽，视频再加时间；模型必须得到位置相关信息。

一种直观做法是在输入向量里加入位置向量。RoPE采用不同办法：在计算注意力前，按位置旋转query/key的成对维度，使点积包含相对位移。不要把它理解成旋转原图片或旋转屏幕上的patch。

## 8. RoPE用二维旋转把相对位置写进点积

取向量的两个维度组成q=(q₁,q₂)，位置m对应角mθ。旋转矩阵为：

```text
R(φ) = [ cosφ  −sinφ ]
       [ sinφ   cosφ ]
q' = R(mθ)q
k' = R(nθ)k
q'ᵀk' = qᵀR(mθ)ᵀR(nθ)k = qᵀR((n−m)θ)k
```

转置的旋转矩阵等于反向旋转，因此两个绝对位置的作用合并为差值n−m。若q/k内容和θ固定，把m、n同时加5，点积不变。这是相对位置性质，不是说真实注意力只由距离决定；真实q/k内容仍然决定分数。

高维query/key按维度对旋转，各对有不同频率。例如常见频率形式为`θⱼ=base^(−2j/d)`；j编号从0开始，d是参与旋转的维度数。快频率适合产生近距离变化，慢频率在更长位移上仍变化缓慢；它们是频率设计，不能严格说“某一维只编码近距离”。

手算令q=k=(1,0)，θ=0.4，m=6、n=10，差为4，点积`cos(1.6)≈−0.0292`；改为m=8、n=12，仍相同。单频结果是振荡曲线，多频也不保证普遍单调衰减。外推更长位置是否有效还取决于训练长度、频率缩放和模型学到的行为。

## 9. M-RoPE：把哪些维度对分配给时间、高、宽

[[figure:l6-position-coordinates]]

一维文本位置只有p；图像需要(h,w)；视频需要(t,h,w)。M-RoPE把query/key的旋转维度分成组，分别使用时间、高和宽位置。不是把一个token复制三遍，也不是画三个独立圆盘就实现全部模型。

在不考虑前文偏移的教学局部坐标里：文本token可用(p,p,p)，让三组看到同一序号，退化到一维位置作用；单图中t固定，高/宽取网格行列；视频同一空间位置跨不同时间组，t改变。

| 示例token | t | h | w |
|---|---:|---:|---:|
| 文本第3位置 | 3 | 3 | 3 |
| 图片第2行第1列 | 0 | 2 | 1 |
| 同图向右一格 | 0 | 2 | 2 |
| 同图向下一格 | 0 | 3 | 1 |

真实混合序列还要叠加位置起点偏移，不能让每张图在整个对话里都无条件从绝对0开始；后续文本位置也需按模型规则推进。空间坐标通常对应进入语言侧的合并后网格，不能把原像素坐标、合并前patch索引和语言侧位置id互换。

## 10. Qwen2.5-VL的时间改进不是“第几帧”换个名字

如果按帧序号计位置，同一段视频按1fps和2fps采样，事件对应的序号不同；只知道“第10帧”无法稳定对应真实第几秒。Qwen2.5-VL将时间位置与实际时间间隔关联，帮助模型表达事件速度与时间定位。

教学上，假设三个视觉时间组对应0、2、4秒，位置尺度s=5，那么t位置可以示意为0、10、20，而不是0、1、2。尺度和取整规则是模型配置，实际实现还要考虑采样fps、时间patch分组与序列偏移；t的数值不是必然等于秒数本身。

这也说明更高采样率不保证所有视频问题都变好：帧数、视觉长度和LLM预算增加，很多帧还可能冗余；较低采样率则可能错过短事件。时序任务必须同时看采样策略与位置机制。

## 11. 可运行RoPE算例与空间合并shape

```python
import math
import torch

def rotate(v, pos, theta=0.4):
    a = pos * theta
    R = torch.tensor([[math.cos(a), -math.sin(a)],
                      [math.sin(a), math.cos(a)]])
    return R @ v

v = torch.tensor([1., 0.])
dot1 = rotate(v, 6) @ rotate(v, 10)
dot2 = rotate(v, 8) @ rotate(v, 12)
print(round(dot1.item(), 4), round(dot2.item(), 4))  # -.0292、-.0292

grid = torch.arange(4 * 4 * 2).reshape(4, 4, 2)
# 先分成2×2局部组，把每组的四个2维向量拼起来
merged = grid.reshape(2, 2, 2, 2, 2).permute(0, 2, 1, 3, 4).reshape(4, 8)
print(grid.shape, merged.shape)  # [4,4,2] → [4,8]
# 真模型再将这8维投影到LLM宽度；这里仅验证空间分组。
```

## 练习

1. 448×672、patch14、空间2×2合并，视觉长度是多少？——答：32×48/4=384，假设尺寸已对齐且无额外标记。
2. AnyRes4块+全局图，为什么不是2304？——答：还需加576，简式合计2880。
3. 原生672合并后也是576，是否等于固定336的输入信息？——答：不等于，编码器所见像素和合并结构不同。
4. 文本位置m/n同时加10，真实注意力一定完全不变吗？——答：固定q/k的RoPE内积具有该性质；真实网络内容状态、掩码与其他上下文变化不能忽略。
5. 单图水平移一格，局部(t,h,w)应如何变？——答：只w加1；t、h保持。
6. 视频t直接用帧号，为什么采样率变化会造成问题？——答：同一实际时间对应不同帧序号，需要时间间隔/时间戳参与编码。

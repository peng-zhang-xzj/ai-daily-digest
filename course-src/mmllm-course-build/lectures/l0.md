# L0 为什么要让模型「看见」:一张图接进语言模型,到底难在哪

建议授课20–25分钟(精讲路线15分钟)。前置知识:知道「模型是一个把输入数字映射成输出数字的函数」「向量是一组数字」即可,不要求读过任何论文。

学完应能:用一句话说清本课要解决的核心矛盾;指出「把一张图接进 LLM」必须解决的三个接口问题;画出贯穿全课的「编码器→连接器→语言模型」数据流;并按两条授课路线(约 8–9 小时完整版 / 90 分钟精讲版)安排学习。

## 1. 核心矛盾:像素和文字根本不在一个世界

人看一张图,几乎瞬间能说出「一只狗在草地上追红色飞盘」。因为在我们脑子里,视觉和语言是打通的。但对机器来说,两种信息的「物理形态」天差地别:

- **图像是稠密数值网格**:一张 336×336 的图,是 336×336×3 个 0–255 的整数(RGB 三通道)。注意:像素值本身是对连续光场的**离散采样**(每个分量是 0–255 的整数),所以别说「像素是数学上连续的」;它的特点是**稠密、高维、带二维空间位置**——一张图就是十几万个数,相邻像素高度冗余。
- **文字是稀疏离散符号**:一句话被切成有限词表里的若干 token,每个 token 是词表中的一个整数 id,本质是**离散、一维顺序、每个 token 信息量高**的。

两者的落差不在「连续 vs 离散」(两边最终都是数字),而在**稠密高维二维冗余信号**与**稀疏一维高信息离散符号**之间。一个只会读文字的大语言模型(LLM),输入端只认识「一串词向量」;你不能直接把像素网格塞给它——维度不对、语义空间不对、它也不知道这堆数字是「图」。

[[fig:core]]

> **本课的一句话**:多模态大模型(Vision-Language Model, VLM)这十年的全部故事,本质就是——想方设法把「像素」翻译成 LLM 能接着处理的「类词向量」,让一个会读文字的大模型顺便「看得见」。

## 2. 把问题拆开:接一张图进 LLM,必须解决三个接口问题

很多人以为「让模型看见」就是「给图像也起个 token 名字」,这是最大的误解。真正要解决的是三件独立的事,缺一不可:

### 问题一:信息提取——从像素里拿到「有用的东西」

原始像素绝大部分是冗余的(相邻像素几乎一样)。直接喂原始像素,模型既算不动,也抓不住重点。需要一个**视觉编码器**先把图压成一组「有语义的特征」:哪里是边缘、哪里是物体、是什么物体。这是 L1 的 CNN、L2 的 CLIP、L6 的 ViT 在做的事。

### 问题二:维度与语义对齐——让视觉特征「说 LLM 的语言」

就算拿到了视觉特征,它的**维度**通常和 LLM 的词向量不一样,它所在的**语义空间**也和 LLM 的词向量空间不是同一个(哪怕是 CLIP,它也只是和「它自己的文本编码器」对齐,不等于和某个 LLM 对齐)。所以中间要一个**连接器**做两件事:把维度对上,把语义「翻译」进 LLM 认识的空间。这是 L3 的 Q-Former、L4 的 MLP、L6 的 Resampler。

### 问题三:序列组织与位置——把图和字排成「一条带位置的序列」

LLM 处理的是「一条序列」,且它靠**位置编码**知道谁先谁后。图是二维的、视频还多一维时间,怎么把它们和文字 token 拼成一条序列、又让模型知道每个视觉 token 在图里的二维位置?这是 L6 的 M-RoPE、L7「图像到底算不算 token」要回答的。

记住这三问,你会发现后面每一讲都在更深地回答其中某一个。

## 3. 一张「心智地图」:编码器 → 连接器 → 语言模型

把三个接口问题串起来,就是贯穿全课的数据流。**请把这张图记在脑子里**,后面六大技术维度都挂在它上面:

[[fig:dataflow]]

**三句话读懂它**:① 图先被编码器变成一组视觉特征;② 连接器把这些特征翻译、对齐成 LLM 认识的「类词向量」;③ 它们和文本 token 拼成一条序列喂给 LLM,LLM 像往常一样逐词生成答案。你会在 L4(LLaVA)第一次看到这三步被最简单地实现出来。

> **一个重要提醒**:这条「编码器→连接器→LLM」是**本课主线**,也是当前多数**理解类** VLM 的骨架,但它**不是唯一架构**。有的模型把图像也离散成 token、和文字塞进同一个词表、用同一套自回归(L7 的 Chameleon/Emu3);有的从头做原生多模态联合训练。主线是帮你拆解新模型的脚手架,不是一条铁律——遇到不走这条路的模型,正好用它当对照。

## 4. 这门课怎么走:三幕 + 六个技术维度

我们不按工程模块平铺,而是沿时间线讲一个演化故事,分三幕;每一幕其实都在把上面那张图的某个零件做强。

| 幕 | 讲次 | 在解决什么 |
|---|---|---|
| 前世(视觉语言地基与桥接) | L1 看图说话 / L2 CLIP / L3 BLIP-2·Flamingo | 打地基:视觉编码器 + 连接器的雏形(L3 的 Flamingo/BLIP-2 已用冻结 LLM,但尚未进入视觉指令范式) |
| 今生(视觉指令与通用 VLM) | L4 LLaVA / L5 数据 / L6 结构 / L7 Tokenizer / L8 训练 / L9 评估 | 视觉指令微调确立范式后,逐个维度做深 |
| 未来 | L10 前沿与开放问题 | 统一生成、任意模态、Agent、安全 |

六个技术维度(数据、结构、分辨率/位置、tokenizer、训练、评估)不是并列的知识点,而是「如何把这条数据流做得更强、更省、更可靠」的六个切面。

## 练习

1. 用一句话说出本课的核心矛盾。 —— 答案:图像是稠密、高维、带二维位置的数值网格(像素是对光场的离散采样),文字是稀疏的一维离散符号序列;要想办法把图像翻译成 LLM 能处理的「类词向量」,让语言模型「看得见」。
2. 「让模型看见」就是「给图像也起个 token 名字」——这句话错在哪? —— 答案:起名字只是表面。真正要解决三件事:从像素提取有语义的特征、把特征维度与语义对齐到 LLM 空间、再把视觉和文本组织成一条带位置的序列。只命名解决不了对齐和序列组织。
3. 连接器(问题二)到底在对齐什么,仅靠 CLIP 够不够? —— 答案:对齐「维度」和「语义空间」。CLIP 只把图像和它自己的文本编码器对齐,维度和训练分布都未必匹配目标 LLM,所以仍需连接器再翻译一次(详见 L2、L4)。
4. 为什么视频比图像在「问题三」上更难? —— 答案:图像是二维(高、宽),视频多一维时间,位置编码要同时表达时/高/宽三种位置并能外推(详见 L6 的 M-RoPE)。
5. 90 分钟精讲里,哪两讲绝不能省,为什么? —— 答案:L1 注意力(它是后面所有 cross-attention 的雏形)和 L6 分辨率—token—位置(决定文档能力与算力瓶颈)。这两处是理解全课的支点。
